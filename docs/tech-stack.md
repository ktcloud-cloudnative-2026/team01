# 기술 스택

Home IoT 시스템 (가정 전자기기 IoT 연동 MSA)

## 기술 스택 선정

| 영역 | 선택 | 왜 | 어디에 | 버린 대안 |
|-----------------------------|---------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------|------------------------------------------------------------|
| 프론트엔드 | Next.js                                           | 가전 기기 시뮬레이터 대시보드를 빠르게 구성하고, 컴포넌트 기반으로 제어 화면(조명·에어컨·난방기기·공기청정기·커튼·엘리베이터 호출)을 확장하기 쉬움 | 시뮬레이터 대시보드                                               | React 단독                                                 |
| 웹 서버 / 리버스 프록시 | Nginx                                             | 정적 파일 제공과 요청 프록시를 통해 프론트엔드 요청 처리를 구성하기 쉬움                                                                           | Envoy Gateway 뒤, Next.js 앞단 (정적 파일 제공·Next.js 요청 전달) | Apache HTTP Server                                         |
| 서비스 언어 | Node.js (Express)                                 | 가볍고 MQTT·REST 처리에 적합하며 팀이 빠르게 익힐 수 있음                                                                                          | 모든 백엔드 서비스                                                | TypeScript/NestJS                                          |
| DB | PostgreSQL                                        | 기기 상태·사용자·제어 이력을 관계형으로 관리하기 쉽고 운영 경험이 풍부함                                                                           | 백엔드 서비스 (서비스별 스키마/DB 분리)                           | \-                                                         |
| 서비스 사이 호출 | REST API (동기) + MQTT (기기 이벤트·제어, 비동기) | 요청/응답은 REST로 단순하게, 기기 상태·제어 메시지는 경량 Pub/Sub인 MQTT로 처리                                                                    | 서비스 간 통신, 시뮬레이터 ↔ 백엔드                               | Kafka, RabbitMQ 등 별도 브로커 (MQTT만 사용해 구성 단순화) |
| 인증 | JWT                                               | 서비스 간 무상태 인증이 가능하고 MSA에 적합                                                                                                        | 인증 서비스, 각 API                                               | 세션 기반 인증                                             |
| Gateway | Envoy Gateway                                     | 쿠버네티스 Gateway API 표준 기반으로 라우팅·TLS 종료·인증 정책을 선언적으로 관리할 수 있음                                                         | 클러스터 외부 진입점                                              | NGINX Ingress Controller, Kong                             |
| CI / CD | GitHub Actions + Argo CD + Jenkins                | 저장소와 바로 연동되고, GitOps로 배포 상태를 선언적으로 관리                                                                                       | 빌드·테스트·이미지 푸시 / 클러스터 배포                           |                                                            |
| 관측 | Prometheus + Grafana (지표), Loki (로그)          | 쿠버네티스 표준에 가깝고 가벼운 구성으로 대시보드·알림 구성이 쉬움                                                                                 | 전 서비스                                                         | ELK 스택                                                   |
